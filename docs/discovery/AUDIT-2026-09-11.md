# SocialFlow — auditoria de continuidade

Data: 11/09/2026. Escopo: Fase 0, conforme `prompts/00-orchestrator.md`.

## Resultado

Manter a plataforma centralizada na VPS da agência, com Docker/Coolify e o monorepo TypeScript já proposto. Não substituir a arquitetura por Postiz, n8n ou Mixpost nesta etapa. A pesquisa justifica uma prova de integração com Postiz antes de construir os conectores e o scheduler completos; não justifica assumir que ele atende ao isolamento e ao fluxo de aprovação do SocialFlow.

A auditoria foi entregue, mas o gate de discovery tem pendências explícitas: elegibilidade TikTok, documentação/review Meta e verificação de versões/licenças das dependências que serão efetivamente instaladas. Nenhuma integração está homologada. Não houve implantação nem publicação social.

## Inventário observado

Foram lidos os 19 arquivos existentes: README; seis documentos em `docs` (ADR, ARCHITECTURE, PRODUCT, RESEARCH, ROADMAP, TESTING); oito prompts; instruções em `agents/AGENTS.md`; plano de banco; compose de referência e exemplo de ambiente.

Não existem `package.json`, lockfile, aplicações, migrations, testes, CI ou repositório Git inicializado nessa pasta. O compose contém somente PostgreSQL e Redis e é uma referência, não uma aplicação executável. Node 24.19.0, pnpm 11.19.0 e Git foram encontrados. O comando Docker não foi encontrado no PATH desta sessão; isso não prova ausência de instalação no computador.

O conteúdo original deve ser preservado. Os adendos de ADR/roadmap identificam decisões atuais sem apagar o planejamento anterior.

## Achados que afetam implementação

| Prioridade | Achado | Encaminhamento |
| --- | --- | --- |
| P1 | O produto é interno à agência; Direct Post TikTok rejeita explicitamente utilitários limitados às contas da própria equipe. | Bloquear promessa de Direct Post público no modelo atual; resolver elegibilidade antes da Fase 5. Ver matriz de APIs. |
| P1 | `Membership.clientId` opcional e “acesso global” não definem a fronteira entre organizações e clientes. | OWNER/ADMIN têm alcance somente dentro da organização autorizada; perfis de cliente exigem vínculo explícito. Sem superadmin implícito. |
| P1 | Filtro no backend, sozinho, não satisfaz isolamento “no backend e banco”. | Planejar RLS, usuário de runtime sem bypass e testes PostgreSQL reais; chaves estrangeiras compostas impedem vínculos entre tenants. |
| P1 | Lock e chave de job não garantem ausência de duplicatas após timeout remoto. | Persistir intenção e estado remoto; resultado incerto exige reconciliação antes de retry. |
| P2 | `PublicationAttempt.idempotencyKey UNIQUE` confunde publicação lógica com múltiplas tentativas. | Separar identidade lógica estável de tentativa numerada antes da Fase 4. |
| P2 | Docker ausente no PATH e nenhuma pipeline existente. | Não declarar Fase 1/CI verdes; executar integração e compose em ambiente Docker antes do aceite. |
| P2 | O roadmap põe teste real Meta antes do scheduler, enquanto o primeiro marco pede agendamento. | Fase 3 valida publicação manual controlada; marco completo somente ao finalizar Fase 4. |

As prioridades são avaliação técnica do SocialFlow, não classificação de vulnerabilidades já presentes em código: ainda não há aplicação.
